## 3. 작업 순서 (모든 봇)

1. **시작 전:** `git pull` → `TASKS.md`·`DECISIONS.md` 읽기. 스펙은 대화가 아니라 `DECISIONS.md` 줄로 확인한다.
2. **시작할 때 그룹에 공유:** 어떤 툴로, 어떤 방식으로, 마감 몇 시 (KST 숫자). 같은 내용을 `TASKS.md` 자기 줄에 적고 push.
3. **시킨 형태 그대로:** 이미지를 시켰으면 이미지. 기획안·설명으로 바꿔 내지 않는다. 헷갈리면 시작 전에 묻는다.
4. **쪼개서 진행:** 큰 작업은 나눈다 (예: 스프라이트는 동작 1줄 4프레임씩).
5. **30분마다 중간 결과물 파일.** "진행 중"이라는 말만 반복하지 않는다.
6. **못 하면 10분 안에 "못 함 + 이유".** 붙잡고 있지 않는다.
7. **제출:** 받은 스펙을 항목별로 대조한 목록 + 파일. 파일은 텔레그램에 직접 첨부하고, 원본은 repo(또는 공유 드라이브)에 둔다. 사진 전송은 압축돼 투명 배경이 사라지므로 검사는 원본으로 한다.
8. **끝나면:** `TASKS.md` 상태·결과물 칸을 고쳐 push.
9. **현황 보고:** 맡은 일 전부를 항목별로 `상태 / 파일 / 마감 시각`. 빠뜨리지 않는다.

### 봇끼리 대화하며 일하기 (11-24 장현님)
1. **손대기 전에 선언:** "@상대봇 X 내가 한다"를 그룹에 먼저 쓰고, TASKS.md 담당 칸에 이름을 넣은 뒤 시작한다. 이미 담당이 있으면 손대지 않는다.
2. **넘길 땐 멘션으로 받았다는 답을 받는다.** "하겠다"고 한 일을 다른 봇이 대신 하지 않는다. 대신 하게 되면 먼저 "@원래담당 내가 한다"고 말한다.
3. **취소된 요청은 하지 않는다.**
4. **완료 보고는 확인 후:** 커밋은 main에 있는지, 파일은 열리는지 본 다음에 "완료".
5. **같은 일을 두 봇이 했으면** 늦은 쪽이 바로 말하고 하나로 합친다.

## 4. 저장소 작업

1. 건드릴 파일·폴더를 먼저 말하고, 겹치면 시작하지 않는다.
2. push 전 `git pull --rebase`.
3. main push 전 빌드 통과 확인. 새 버전은 `package.json`의 `version`만 올리면 CI가 릴리스를 만든다.
4. 화면이 바뀌는 변경은 장현님께 이미지로 먼저 보여 주고 승인 후 버전을 올린다.
5. 토큰·키는 채팅·커밋 금지. GitHub Secrets나 서버 환경변수로만. 키는 장현님이 각 봇 환경에 직접 넣는다.

## 5. 채팅 관리 (담당: 클로디)

봇들이 같은 메시지를 동시에 받아 서로의 답을 못 보고 겹쳐 답하는 일을 막는다.

1. **멘션된 봇만 답한다.** 멘션 없는 일반 요청은 클로디만 답한다.
2. **답장(reply)은 봇에게 안 보일 수 있다.** 다른 봇 메시지 바로 뒤의 멘션 없는 짧은 말은 그 봇에게 한 말로 보고 다른 봇은 빠진다. 확실히 시킬 땐 @멘션.
3. **"뭐 했어?"·"끝났어?" 같은 확인 질문은 한 봇만 답한다.** TASKS.md 담당 봇이 답하고, 담당이 여럿이거나 애매하면 클로디만 답한다. 다른 봇은 그걸 하러 달려들지 않는다.
4. **한 질문에 한 봇.** 다른 봇은 앞 답이 틀렸을 때만 짧게 정정한다.
5. **클로디가 교통정리.** 겹치거나 섞이면 클로디가 정리해서 필요한 봇에게 멘션으로 넘긴다.
6. **봇은 그룹 사진을 못 본다.** 사진 내용을 글로 옮기지 말고 파일을 첨부해서 넘긴다.
7. **경고·알림은 한 번, 한 봇만.**
8. **보고:** 일반방 답은 짧게. 최종 완료 보고·정기 브리핑만 [📅 정기 업무·브리핑] 토픽. 장현님 보고에 커밋 해시·빌드 번호는 넣지 않고, 결정이 필요하면 선택지 + 추천 하나.
9. **추측 금지.** 막히거나 판단이 다르면 바로 공유. 다른 봇 말은 확인하고 반영.
